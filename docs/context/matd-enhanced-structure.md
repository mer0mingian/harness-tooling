# MATD Enhanced Workspace Structure

## Overview

This document defines the enhanced MATD workspace structure with complete traceability from Product Requirements Documents (PRDs) through Solution Designs (SDs) to executable Specifications (Specs).

## Full Folder Structure

```
project-root/
├── matd-config.yml                          # Configuration file
├── prds/
│   ├── PRD-001.md                           # Product Requirement Document 1
│   ├── PRD-002.md                           # Product Requirement Document 2
│   └── ...
├── solution-designs/
│   ├── SD-001.md                            # Links to PRD-001
│   ├── SD-002.md                            # Links to PRD-001
│   ├── SD-003.md                            # Links to PRD-002
│   └── ...
├── specs/
│   ├── SPEC-0001/
│   │   ├── spec.md                          # Specification content
│   │   ├── plan.md                          # Implementation plan
│   │   ├── tasks.md                         # Task breakdown
│   │   ├── dependency-map.md                # Dependencies on other specs
│   │   └── design/                          # Optional spec-specific designs
│   │       ├── architecture.md
│   │       └── diagrams/
│   ├── SPEC-0002/
│   │   ├── spec.md
│   │   ├── plan.md
│   │   ├── tasks.md
│   │   └── dependency-map.md
│   └── ...
├── specs_archive/
│   └── SPEC-0042/                           # Entire archived spec folder
│       ├── spec.md
│       ├── plan.md
│       └── ...
├── tests/
│   ├── unit/
│   │   ├── test_authentication.py           # spec_id: SPEC-0001
│   │   └── test_user_service.py             # spec_id: SPEC-0001, SPEC-0003
│   ├── integration/
│   │   └── test_api_endpoints.py            # spec_id: SPEC-0002
│   └── acceptance/
│       └── test_login_flow.py               # spec_id: SPEC-0001
└── adrs/
    ├── ADR-001-auth-strategy.md             # Referenced by SD-001
    └── ...
```

## Spec Folder Structure

Each spec folder contains:

**`specs/SPEC-0001/`**

- **`spec.md`** - The specification itself with frontmatter:
  ```yaml
  ---
  spec_id: SPEC-0001
  title: Login Flow Implementation
  solution_design: SD-001
  prd: PRD-001
  status: in-progress
  created: 2026-06-09
  ---
  ```

- **`plan.md`** - Implementation plan generated by SpecKit planning workflow

- **`tasks.md`** - Dependency-ordered task breakdown

- **`dependency-map.md`** - Dependencies on other specs:
  ```markdown
  # Dependencies for SPEC-0001
  
  ## Depends On
  - SPEC-0003: User Service (requires user lookup)
  - SPEC-0004: Token Service (requires JWT generation)
  
  ## Blocked By
  None
  
  ## Blocks
  - SPEC-0002: Session Management (needs login to create sessions)
  ```

- **`design/`** - Optional spec-specific design artifacts (diagrams, architecture notes)

## Solution Design Numbering

Solution Designs are numbered **globally** (not per-PRD) but maintain explicit PRD linkage via frontmatter:

```yaml
---
sd_id: SD-001
title: Authentication Architecture
prd: PRD-001
requirements: [R1, R2, R3]
adrs: [ADR-001]
---
```

This allows:
- One PRD to have multiple SDs (different solution approaches)
- One SD to potentially reference multiple PRDs (cross-cutting concerns)
- Clear audit trail via metadata

## Test Linking Mechanism

Tests link to specs via pytest markers and docstrings:

**Python Example:**
```python
import pytest

@pytest.mark.spec("SPEC-0001")
@pytest.mark.spec("SPEC-0003")
def test_user_login_validation():
    """
    Tests login validation logic.
    
    Spec Coverage:
    - SPEC-0001: Login Flow Implementation (validates credentials)
    - SPEC-0003: User Service (queries user database)
    """
    # test implementation
```

**TypeScript Example:**
```typescript
/**
 * @spec SPEC-0002
 * @description Tests session creation after successful login
 */
describe('Session Management', () => {
  it('creates session on login', () => {
    // test implementation
  });
});
```

Test discovery tools can extract spec references from markers/docstrings to generate coverage reports.

## Configuration Schema

**`matd-config.yml`:**

```yaml
# MATD Configuration
version: "1.0"

# Path configuration (all paths relative to project root)
paths:
  prds: "prds"                                # Product Requirement Documents
  solution_designs: "solution-designs"        # Solution Design documents
  specs: "specs"                              # Active specifications
  specs_archive: "specs_archive"              # Archived specifications
  tests: "tests"                              # Test directory root
  adrs: "adrs"                                # Architecture Decision Records

# Numbering configuration
numbering:
  prd_prefix: "PRD"                           # PRD-001, PRD-002
  prd_width: 3                                # Zero-padding width
  sd_prefix: "SD"                             # SD-001, SD-002
  sd_width: 3                                 # Zero-padding width
  spec_prefix: "SPEC"                         # SPEC-0001, SPEC-0002
  spec_width: 4                               # Zero-padding width

# Spec folder structure
spec_folder:
  spec_file: "spec.md"                        # Main specification
  plan_file: "plan.md"                        # Implementation plan
  tasks_file: "tasks.md"                      # Task breakdown
  dependency_file: "dependency-map.md"        # Dependencies
  design_folder: "design"                     # Optional designs

# Test configuration
tests:
  marker_name: "spec"                         # Pytest marker name
  coverage_report: "test-coverage-by-spec.md" # Generated coverage report
```

## Migration from Flat Structure

**Step 1: Identify existing specs**
```bash
ls specs/*.md  # Find all flat spec files
```

**Step 2: Create spec folders**
```bash
for spec in specs/SPEC-*.md; do
  spec_id=$(basename "$spec" .md)
  mkdir -p "specs/$spec_id"
  mv "$spec" "specs/$spec_id/spec.md"
done
```

**Step 3: Generate missing artifacts**
Run SpecKit commands to generate `plan.md`, `tasks.md` for each spec:
```bash
for spec_dir in specs/SPEC-*/; do
  spec_id=$(basename "$spec_dir")
  cd "$spec_dir"
  # Run SpecKit plan generation
  # Run SpecKit tasks generation
  # Create empty dependency-map.md
  touch dependency-map.md
done
```

**Step 4: Add traceability metadata**
Update frontmatter in `spec.md`, `SD-*.md`, `PRD-*.md` files to include cross-references.

**Step 5: Update tests**
Add `@pytest.mark.spec("SPEC-XXXX")` markers to existing tests.

## Benefits

1. **Complete Audit Trail**: Follow any requirement from PRD through SD to implementation
2. **Clear Dependencies**: `dependency-map.md` makes spec ordering explicit
3. **Organized Artifacts**: Each spec is self-contained with plan, tasks, designs
4. **Flexible Testing**: Tests reference specs, not vice versa
5. **Easy Archival**: Move entire spec folder to archive
6. **Configurable Paths**: Teams can adapt structure via `matd-config.yml`

## Traceability Query Examples

**Find all specs for PRD-001:**
```bash
grep -r "prd: PRD-001" specs/*/spec.md
```

**Find tests covering SPEC-0001:**
```bash
grep -r "@pytest.mark.spec.*SPEC-0001" tests/
```

**Check spec dependencies:**
```bash
cat specs/SPEC-0001/dependency-map.md
```

This structure provides complete traceability while maintaining flexibility for different project needs.
