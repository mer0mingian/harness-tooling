# MATD Artifact Mapping

**Comprehensive mapping of all artifacts produced by the MATD workflow and their locations.**

Created: 2026-06-09  
Status: Living document — update as workflow evolves

---

## Overview

The MATD (Multi-Agent Test-Driven Development) workflow produces artifacts across four phases: **Discovery**, **Solution Design**, **Refinement**, and **Implementation**. This document maps every artifact to its storage location in the workspace-template structure.

**Key Concepts:**
- **Persistent artifacts** (Product Brief, System Constitution) — live indefinitely, evolve with the product
- **Transient artifacts** (PRDs, Specs) — archived on completion with permanent IDs
- **Generated artifacts** (C4 diagrams) — regenerated via litho, not hand-edited
- **Traceability IDs** — permanent, monotonic, never renumbered: `PRD-NNN`, `SPEC-NNNN`, `REQ-NNN`

## Per-Phase Artifact Table

### Phase 1: Discovery (matd-discovery extension)

| Agent | Artifact | Path | Template | Persistent |
|-------|----------|------|----------|------------|
| `matd-specifier` | Product Brief | `product/brief.md` | `product-brief-template.md` | ✅ Persistent |
| `matd-specifier` | PRD (change request) | `product/prd/PRD-NNN-<slug>.md` | `prd-schema.yml` → rendered | ❌ Transient → archived |
| `matd-specifier` | PRD context file | `product/context/PRD-NNN-<slug>.context.md` | (free-form extended context) | ❌ Transient → archived |
| `matd-specifier` | PRD traceability index | `product/prd/index.yml` | (script-generated) | ✅ Persistent |
| `matd-specifier` | SDP Initiative payload | `product/prd/PRD-NNN-<slug>.sdp.json` | `sdp-initiative-template.yml` | ❌ Transient (optional) |
| `matd-specifier` | System Constitution | `architecture/system-constitution.md` | `constitution-template.md` | ✅ Persistent |

**Notes:**
- PRD uses stable internal `PRD-NNN` IDs; SDP key (`SDP-1234`) bound 1:1 via index
- Product Brief = business invariants; System Constitution = technical invariants; PRD = change request
- PRD context centralised in `product/context/` (one file per PRD) to keep structured PRD concise

### Phase 2: Solution Design (matd-solution-design extension)

| Agent | Artifact | Path | Template | Persistent |
|-------|----------|------|----------|------------|
| `c4-context` | C1 Context diagrams | `architecture/c4/context.svg` | (litho-generated) | ✅ Generated (re-gen via litho) |
| `c4-container` | C2 Container diagrams | `architecture/c4/container-*.svg` | (litho-generated) | ✅ Generated |
| `c4-component` | C3 Component diagrams | `architecture/c4/component-*.svg` | (litho-generated) | ✅ Generated |
| `matd-architect` | Solution Design | `architecture/design/FEAT-NNN-solution-design.md` | `solution-design-template.md` OR StepStone 9-section alternative (spec 004) | ❌ Transient → archived with spec |
| `matd-architect` | ADR (contested decisions) | `architecture/decisions/NNN-<topic>.md` | `adr-template.md` | ✅ Persistent (numbered, never removed) |
| `matd-architect` | API contracts | `architecture/design/api-contracts-FEAT-NNN.md` | (embedded in Solution Design or separate) | ❌ Transient |
| `matd-architect` | Data contracts | `architecture/design/data-contracts-FEAT-NNN.md` | (embedded in Solution Design or separate) | ❌ Transient |

**Notes:**
- C4 diagrams are **generated** (litho reads codebase) — do NOT hand-edit SVG files
- ADRs are persistent (numbered, accumulate over time); Solution Designs are transient (archived with specs)
- Alternative StepStone 9-section Solution Design template defined in spec 004 (future)

### Phase 3: Refinement (matd-refinement extension)

| Agent | Artifact | Path | Template | Persistent |
|-------|----------|------|----------|------------|
| `matd-architect` | Implementation plan | `plans/NNN-<phase-name>.md` OR `plans/task-breakdown-FEAT-NNN.md` | (flat structure, numbered/dated) | ❌ Transient |
| `matd-qa` | Test design | `docs/features/${FEATURE_ID}/test-design-${FEATURE_ID}.md` OR `docs/tests/test-design/test-design-${FEATURE_ID}.md` | `test-design-template.md` | ❌ Transient |
| `matd-qa` | E2E/Acceptance tests (RED) | `tests/acceptance/test_*.py` | (pytest format) | ❌ Transient (code) |
| `matd-qa` | UAT test plans | `tests/uat/uat-checklist-*.md` | (manual test checklist) | ❌ Transient |
| `matd-architect` | Task list | `plans/task-breakdown-FEAT-NNN.md` | (numbered tasks with story points) | ❌ Transient |

**Notes:**
- Plans are flat structure (no subdirectories); numbered (`001-`, `002-`) or dated (`2026-Q2-roadmap`)
- Test design artifact exists at command level but path varies (configurable via `matd-config.yml`)
- E2E tests written in RED state (failing with `MISSING_BEHAVIOR` or `ASSERTION_MISMATCH`)

### Phase 4: Implementation (matd-implement-tdd extension)

| Agent | Artifact | Path | Template | Persistent |
|-------|----------|------|----------|------------|
| `matd-dev` | Source code | `components/*/src/**/*.py` (or language-specific) | (project structure) | ✅ Persistent (code) |
| `matd-dev` | Unit tests | `tests/unit/test_*.py` | (pytest format) | ✅ Persistent (code) |
| `matd-dev` | Integration tests | `tests/integration/test_*.py` | (pytest format) | ✅ Persistent (code) |
| `matd-dev` | Implementation notes | `docs/features/${FEATURE_ID}/impl-notes-${FEATURE_ID}.md` | `implementation-notes-template.md` | ❌ Transient |
| `matd-dev` | Acceptance tests (GREEN) | `tests/acceptance/test_*.py` | (updated from RED → GREEN) | ✅ Persistent (code) |

**Notes:**
- Source code lives in `components/` as git submodules (multi-repo) or direct folders (single-repo)
- Unit tests written first (RED), then implementation code (GREEN), then refactor
- Implementation notes track RED→GREEN evidence + refactoring steps
- Acceptance tests transition from RED (Phase 3) to GREEN (Phase 4)

### Cross-Cutting Artifacts

| Artifact | Path | Template | Persistent | Notes |
|----------|------|----------|------------|-------|
| Research/Spikes | `research/<topic>.md` | (free-form) | ❌ Transient | Flat structure; tech evaluations, POCs |
| Traceability index | `product/prd/index.yml` | (script-generated) | ✅ Persistent | `PRD-NNN ↔ SDP-key ↔ SPEC-NNNN ↔ Epic-key` mappings |
| Archived specs | `specs_archive/FEAT-*.md` | (moved from `specs/`) | ✅ Persistent (archived) | IDs retained, never reused |
| Archived PRDs | `product/prd/_archive/PRD-*.md` | (moved from `product/prd/`) | ✅ Persistent (archived) | IDs retained, never reused |
| MATD config | `.specify/matd-config.yml` | (default shipped) | ✅ Persistent (workspace) | Agent timeout, test patterns, artifact paths |
| Jira config | `.specify/jira-config.yml` | `jira-config-scaffold.yml` (marketplace) | ✅ Persistent (workspace, gitignored) | Team UUIDs, custom field IDs, transition IDs |

**Notes:**
- Traceability index is the single source of truth for `PRD ↔ SDP ↔ Spec ↔ Epic` mappings
- IDs are permanent (monotonic sequences); deprecate only, never renumber
- Jira config scaffold ships in marketplace; live config lives in workspace only (OSS-safe boundary)
